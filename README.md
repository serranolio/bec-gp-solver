# bec-gp-solver

Numerical solver for the Gross-Pitaevskii equation (GPE) describing
N-component spin-orbit-coupled Bose-Einstein condensates. Supports 1D, 2D,
3D Cartesian, and 3D axially-symmetric geometries. Designed for parallel
parameter sweeps on HPC clusters via SLURM array jobs.

---

## Physics background

A BEC is described by a macroscopic wavefunction ψ governed by the
Gross-Pitaevskii equation — a nonlinear Schrödinger equation:

```
i ∂ψ/∂t = [-∇² + U(r) + g|ψ|²] ψ
```

For a spin-orbit-coupled N-component system this generalizes to a vector
equation per component i:

```
i ∂ψ_i/∂t = [-∇² + 2(σ_z)_i(-i∂/∂z) + (σ_z)_i² + Δ_i + q_i] ψ_i
           + (Ω/2 · ψ)_i
           + Σ_j g_ij n_atoms |ψ_j|² ψ_i
           + [V_trap + V_lattice] ψ_i
```

where σ_z encodes spin-orbit coupling, Ω is the tridiagonal Rabi coupling
matrix, Δ is the detuning diagonal, q is the quadratic Zeeman shift per
component, g_ij is the N×N interaction matrix, V_trap is the harmonic trap,
and V_lattice = 2 Ω_L sin²(k_L z) is the optical lattice.

Ground states are found via imaginary-time evolution: replacing i∂/∂t with
∂/∂t and subtracting the chemical potential μ = ⟨H⟩/⟨ψ|ψ⟩ at each step
prevents the wavefunction from decaying to zero.

---

## Units

All internal quantities use recoil units derived from the recoil frequency
`f_recoil`:

| Quantity | Unit                        |
|----------|-----------------------------|
| Energy   | `ħ × 2π × f_recoil`         |
| Length   | `ħ / sqrt(2 m E_recoil)`    |
| Time     | `ħ / E_recoil`              |

Input files specify physical frequencies in Hz and times in ms. The config
loader converts everything to recoil units before passing to the solver.

## Installation

The project uses [pixi](https://prefix.dev) for environment management.

```bash
git clone https://github.com/serranolio/bec-gp-solver
cd bec-gp-solver
pixi install
pip install -e .
```

The `pip install -e .` step registers `bec_gp_solver` as an installed package
in editable mode, meaning it can be imported from any directory without
modifying `sys.path`, and any changes to the source files take effect
immediately without reinstalling. See the **Importing from other directories**
section for details.

## HPC workflow

### Step 1 — Configure the physics in `base.toml`

Edit `configs/base.toml` to set the physical parameters that are fixed across
your sweep. The key sections are `[system]`, `[trap]`, `[geometry]`, and
`[simulation]`. The `[sweep]` section holds default per-job values that will
be overridden by `generate_sweep_files.py`.

**Geometry configuration** — all three axes are always declared. Set unused
axes to `n = 0` and their factor to `0.0`:

```toml
[geometry]
kind         = "3d_axial"
nx           = 64
ny           = 0       # unused — set to 0 to exclude this axis
nz           = 512
lx_rx_factor = 1.5     # box size = factor × Thomas-Fermi radius
ly_ry_factor = 0.0     # unused — set to 0.0 to exclude this axis
lz_rz_factor = 2.5
```

The loader automatically filters out zero-valued axes before constructing the
geometry, so all four geometry kinds share the same TOML structure:

| `kind`     | `nx` | `ny` | `nz` |
|------------|------|------|------|
| `1d_cart`  | 0    | 0    | N    |
| `2d_cart`  | N    | 0    | N    |
| `3d_cart`  | N    | N    | N    |
| `3d_axial` | N    | 0    | N    |

### Step 2 — Define the sweep in `generate_sweep_files.py`

Edit the `SWEEP` dict at the top of the script to define the axes of your
parameter sweep. Every combination will become one job:

```python
SWEEP = {
    'ramp_time_ms'   : list(range(10, 110, 10)),  # 10 ramp durations
    'total_time_ms'  : [300.0],
    'delta_start_hz' : [5000.0],
    'delta_end_hz'   : [-1500.0],
    'omega_l_start'  : [0.2],
    'omega_l_end'    : [0.2],
    'sample'         : list(range(10)),            # 10 noise realisations
}
```

Then run:

```bash
python generate_sweep_files.py --base configs/base.toml --out configs/sweep/
# Generated 100 job configs in configs/sweep/
# SLURM array range: 0-99
```

### Step 3 — Submit to SLURM

```bash
N=$(( $(wc -l < configs/sweep/job_list.txt) - 1 ))
sbatch --array=0-$N jobscript.sh
```

Each node independently runs:

```bash
python run_simulation.py \
    --config     configs/sweep/job_0042.toml \
    --output-dir output/ \
    --gs-dir     ground_states/
```

### Step 4 — Ground state caching

The ground state depends only on the initial trap, scattering lengths, and
initial lattice depth and detuning — not on the ramp parameters or the sample
index. The first job to need a given ground state computes it via
imaginary-time cooling with `solve_ivp` and saves the result to
`ground_states/`. All subsequent jobs with the same initial physics load it
directly, so the computation is never repeated regardless of sweep size.

The cache filename encodes the relevant physics as a short hash:

```
gs_delta_5000hz_omega_0.20_a3f82c9d1b.npy
```

> **Tip for large sweeps:** before submitting the full array, run a single
> job with `observables = []` and `total_time_ms` set just long enough to
> complete imaginary-time cooling. This pre-populates the ground state cache
> so no array job wastes walltime on it.

### Step 5 — Outputs

Each job writes one `.npy` file per requested observable to `output/`.
Filenames encode the sweep parameters so results from different nodes never
collide:

```
sample_1_ramp_50ms_di_5000hz_df_-1500hz_ol_0.20_polarization.npy
sample_1_ramp_50ms_di_5000hz_df_-1500hz_ol_0.20_populations.npy
```

Supported observables (set under `[simulation]` in the TOML):

| Name               | Shape                           | Description                     |
|--------------------|--------------------------------|---------------------------------|
| `polarization`     | `(n_frames,)`                  | `(n₀ − n₁) / (n₀ + n₁)`        |
| `populations`      | `(n_components, n_frames)`     | Per-component atom number       |
| `wavefunction`     | `(n_comp × N_total, n_frames)` | Full complex wavefunction       |
| `momentum_density` | `(n_comp, N_total, n_frames)`  | `|ψ̃(k)|²` via forward transform |

## Running a single simulation

```python
import tomllib
import numpy as np
from scipy.integrate import solve_ivp
from bec_gp_solver.config_loader import load_config, _compute_derived
from bec_gp_solver.gp_equation   import get_rhs

with open("configs/base.toml", "rb") as f:
    cfg = tomllib.load(f)

geo, rhs_kwargs = load_config("configs/base.toml")
d = _compute_derived(cfg)

# --- imaginary-time ground state ---
rhs_imag = get_rhs(geo=geo, mode='imaginary', **rhs_kwargs)
# build a Thomas-Fermi initial guess psi0 ...
sol_gs = solve_ivp(rhs_imag, t_span=(0, 1000), y0=psi0,
                   method='RK45', t_eval=[1000], rtol=1e-6, atol=1e-9)
psi_gs = sol_gs.y[:, -1]

# --- real-time evolution ---
rhs_real = get_rhs(geo=geo, mode='real', **rhs_kwargs)
t_total  = cfg['sweep']['total_time_ms'] * 1e-3 / d['t_unit']
t_eval   = np.linspace(0, t_total, cfg['simulation']['t_frames'])

sol = solve_ivp(rhs_real, t_span=(0, t_total), y0=psi_gs,
                method='RK45', t_eval=t_eval, rtol=1e-6, atol=1e-9)

psi_t = sol.y   # shape (n_comp × N_total, n_frames)
```

## Importing from other directories

Because the package is installed with `pip install -e .`, you can import
`bec_gp_solver` from any Python script or notebook on the same machine:

```python
from bec_gp_solver.geometry      import make_geometry
from bec_gp_solver.gp_equation   import get_rhs
from bec_gp_solver.config_loader import load_config, _compute_derived
```

No `sys.path` manipulation needed. On the cluster, run `pip install -e .`
once after cloning into your home directory. To verify:

```bash
python -c "import bec_gp_solver; print('ok')"
```

## Supported geometries

All geometry classes are instantiated through `make_geometry` and expose an
identical interface:

```python
geo = make_geometry('3d_axial', sizes=(64, 512), lengths=(lx, lz))
```

| `kind`     | Description                      | `sizes`          | `lengths`          |
|------------|----------------------------------|------------------|--------------------|
| `1d_cart`  | 1D Cartesian (FFT)               | `(nz,)`          | `(lz,)`            |
| `2d_cart`  | 2D Cartesian (FFT)               | `(nx, nz)`       | `(lx, lz)`         |
| `3d_cart`  | 3D Cartesian (FFT)               | `(nx, ny, nz)`   | `(lx, ly, lz)`     |
| `3d_axial` | Cylindrical (DHT in r, FFT in z) | `(nx, nz)`       | `(lx, lz)`         |

Every geometry exposes:

```python
geo.grids            # real-space coordinate meshgrids
geo.kgrids           # momentum-space coordinate meshgrids
geo.dv               # real-space volume elements,      shape (N_total,)
geo.dvk              # momentum-space volume elements,  shape (N_total,)
geo.sizes            # tuple of grid point counts
geo.lengths          # tuple of box sizes (recoil units)
geo.spacings         # array of grid spacings
geo.dz               # axial grid spacing (float)

geo.kinetic(psi)           # applies -∇²/2
geo.grad_z(psi)            # applies -i ∂/∂z
geo.forward_transform(psi) # ψ(r) → ψ̃(k)
geo.inverse_transform(psi) # ψ̃(k) → ψ(r)
```

`psi` can be shape `(N_total,)` for a single component or
`(n_components, N_total)` for a multi-component state. All operators
act independently on each component with no cross-talk.
